# ButterflyAI data

This folder holds every dataset used by the three ButterflyAI models, and this README is the **single source of truth** for which images each model uses for training, validation and testing.

> **Status (2026-09-24):** this README describes the planned `data/` layout. The images have **not been moved yet**; the "Currently at" column says where each dataset lives today.

## Layout

```
data/
├── README.md        this file
├── move_log.csv     every file moved into data/ (src, dst, status), so any move can be undone
├── images/<source>/ image files only, never edited
├── metadata/<source>/ the original CSVs/spreadsheets that came with each source, untouched
├── splits/<model>/  CSVs that define training/validation/test (generated by scripts/)
├── superseded/      old copies and retired files, under their old paths; safe to delete once you're happy
└── scripts/         move_data.py (moved everything here), make_splits.py (builds splits/)
```

### Split files (built by `python data/scripts/make_splits.py`)

| File | Rows | Columns |
|---|---|---|
| `splits/feeding/dev_pool.csv` | 4,750 | `image_path, label, photo_type, group, fold` |
| `splits/feeding/test1.csv` | 6,353 | `image_path, label, source, image_url, plant_scientific_name` |
| `splits/feeding/test2_ontario.csv` | 2,785 | `image_path, label` |
| `splits/plant/dev_pool.csv` | 19,684 | `image_path, label, kind (plain/composite), group, fold` |

| `splits/removed.csv` | 2,007 | every row left out of a split, with `split` and `reason` |

`image_path` is relative to the repo root. `fold` (0–4) comes from grouped, stratified 5-fold cross-validation (seed 42). Rows in the same `group` always share a fold. Plant species names are normalized (`Cirsium_arvense`, `Sisymbrium_loeselii`).

## Rules

1. **Images are stored once, grouped by where they came from**, in `data/images/<source>/`. They're never sorted into `train/` or `test/` folders.
2. **A dataset's role is set by a CSV** in `data/splits/<model>/`. Training and evaluation scripts read only from `data/splits/`.
3. **Development pool = training + validation.** Models are compared, tuned and thresholded with grouped k-fold cross-validation on the pool. The final model is then trained on the whole pool.
4. **Test sets are real photos only, never used to choose between models**, and scored once at the end.
5. **Related images stay together.** A superimposed image stays with its source photo, and a plain flower photo stays with its composite versions. Every split uses these groups.
6. **Superimposed and composite images are reported separately** from real-photo results.

## Image types

| Type | What it is | Used by |
|---|---|---|
| Real butterfly photos | Photos of butterflies, labelled feeding (F) / non-feeding (N) | feeding, monarch |
| Superimposed (feeding) | A butterfly cut from a **real non-feeding photo**, pasted onto a flower. Label: **N** | feeding |
| Detectron composites (plant) | A butterfly pasted onto a **plain photo of a target plant**. Label: **plant species** | plant ID |
| Plain flower photos | One of the 10 target plants, no butterfly. Label: plant species | plant ID |

- **Test:** the gold set is the plant test set. Its feeding labels are also used, as part of Feeding Test 1 (source `inat_2024_gold`).

## What the models share

**One test set, no training data.** The Joint gold standard is a test set for both models: its plant labels test the plant model, and its feeding labels are part of Feeding Test 1. Sharing a *test* set is fine, as long as neither model trains on it or uses it to choose between models. No development pool shares images with another model's test set.

Open question: we don't know which photos the butterflies in the plant composites were cut from. They may be the same individuals as in the feeding photos. That's harmless for separate tasks, but worth confirming.
